## 2. 앱용 필터: 0.5초 지연 방식 (방법 B)

**목적:** 오프라인 필터(앞뒤 데이터 사용)는 앱에서 쓸 수 없다. 실시간에서도 정확도를 유지할 방법.

**결정 (2026-10-16):** 0.5초 늦게 계산하는 대신 앞뒤 데이터를 쓰는 방식. 1초 지연 요구사항(NFR-01) 안.

**구현**
- `indoornav/pdr/preprocess.py` → `delayed_filtfilt()`
  - 0.1초마다 최근 3초 구간을 앞뒤로 필터하고, [지금 − 0.5초 − 0.1초, 지금 − 0.5초) 구간만 확정.
- `indoornav/pdr/params.py` → `PreprocessParams.mode` = `"offline"` | `"delayed"` | `"causal"`, `delay_s`, `window_s`, `hop_s`
  - 예전 설정 파일의 `causal = true/false`도 읽히도록 호환 처리 (`_build()`).

**결과** (v1 설정, eval 평균)

| 필터 | 걸음 % | 거리 % | 폐루프 종점 % |
|---|---|---|---|
| offline | 3.6 | 8.2 | 1.9 |
| causal | 7.2 | 13.2 | 2.7 |
| **delayed 0.5 s** | **3.7** | **8.4** | **2.1** |
| delayed 0.3 s | 3.7 | 8.0 | 1.8 |

**알려진 제약:** `step.method = "adaptive"`(§5)에는 아직 적용 안 됨. adaptive는 내부에서 오프라인 필터를 쓴다.

**테스트:** `test_delayed_filter_matches_offline`, `test_legacy_causal_key`

## 3. 튜닝 방식을 교차검증으로 변경 + 걸음 빈도 보폭 모델 (보류) → v2

**목적:** 세션이 10개뿐이라 tune 4 / eval 6 고정 분할은 데이터를 너무 버린다.

**구현**
- `scripts/tune_pdr.py` 전면 수정
  - `--method cv`(기본): 세션 하나씩 빼고 나머지로 값을 고른 뒤 빼둔 세션으로 오차 측정. 10번 반복.
  - 반복마다 골라진 값을 표로 출력 → 값이 흔들리면 데이터 부족 신호.
  - 마지막에 전체 세션으로 다시 골라 저장. `--save` 시 `docs/tuning_log.md`에 기록 자동 추가.
  - `--method split`: 예전 tune/eval 방식.
  - 같은 (설정, 세션) 결과를 캐시해서 135조합 × 10세션도 10초 내외.
- 보폭 모델 옵션 `length.model = "weinberg_freq"`: `L = K·r^e + k_freq·f + offset` (f = 걸음 빈도)
  - `step_length.py` → `step_frequency()`, `calibrate_freq()`

**결과**

| 보폭 모델 | 교차검증 거리 평균 | 최대 |
|---|---|---|
| weinberg | 9.1% | 20.2% |
| weinberg_freq | 7.9% | 13.7% |

**weinberg_freq 보류 이유:** 숫자는 좋지만 골라진 값이 물리적으로 말이 안 됨. 지수가 매번 탐색 하한(0.15)에 붙고, 상수항 −1.0 m, K가 반복마다 0.95~1.82, 한 반복에서는 걸음 빈도 계수가 음수(빨리 걸을수록 보폭이 짧아짐). 세션 10개로 숫자 3개를 맞춘 과적합으로 판단. **세션 20개 이상에서 재비교.**

**산출:** `pdr_tuned_v2.toml` (peak, 지수 0.55, K 0.359)

## 4. 매우 느린 걸음에서 걸음을 놓치는 원인 분석

**문제:** 매우 느린 걸음(69보)을 62보(−10%)로 셈. NFR-04(걸음 검출 95%) 미달. 실제 사용자(시각장애인)와 가장 가까운 상황.

**발견 1 — 합계가 맞아도 개별 걸음은 틀린다**
- 걸음 간격이 중앙값의 0.6배 미만(가짜 의심) / 1.6배 초과(놓침 의심)를 셈.
- 느린 폐루프(203보): 합계는 정확했지만 이상 간격 87개. 가짜와 놓침이 상쇄된 것.
- 놓친 자리의 후보 봉우리 돌출은 0.29~0.49, 채택된 걸음은 0.50~0.75 → 기준값으로 구분 불가.

**발견 2 — 느린 걸음에서는 수직 가속도에 걸음 리듬이 거의 없다** (그림: `docs/figures/slow03_zoom.png`)

걸음 주파수 근처 에너지 비중 (0.2~3 Hz 전체 대비):

| 세션 | 걸음 주파수 | 수직 가속 | 수평 가속 | 기울기 회전 |
|---|---|---|---|---|
| S1_normal_01 | 1.24 Hz | 57% | 74% | 72% |
| S1_slow_03 | 0.63 Hz | **1%** | **40%** | 24% |

- 보통 걸음: 걸음마다 위아래 출렁임 → 수직 가속으로 잡힘.
- 매우 느린 걸음: 위아래 출렁임이 거의 없고 한 걸음에 봉우리 두 개. 대신 수평 흔들림·몸 기울기에 걸음 리듬이 실림.
- **결론:** 기준값 튜닝으로 해결할 문제가 아니라, 속도에 따라 신호를 바꿔야 함.

## 5. 속도 적응형 걸음 검출 (`step.method = "adaptive"`) → v3

**구현:** `indoornav/pdr/step_adaptive.py` → `detect_steps_adaptive()`
1. 6초 창(1초 간격)마다 수직 흔들림 표준편차가 `slow_energy` 미만이면 느린 걸음 모드. 앞뒤 2창 다수결로 다듬음.
2. 모드별 신호(보통: 수직 가속 0.3~3 Hz, 느림: 가속도 크기 0.3~1.5 Hz)에서 자기상관으로 걸음 주기 T 추정.
3. 신호를 최근 3초 흔들림 크기로 나눠 단위를 맞춘 합성 신호에서 봉우리 검출 (`adaptive_prom`).
4. 직전 걸음과 0.6·T보다 가까우면 같은 걸음 → 돌출 큰 쪽만 남김.
5. 주기성(`min_quality`)이 약하거나 흔들림(`min_energy`)이 작으면 걷지 않는 구간 → 걸음 없음.

- `pipeline.py`: 걸음마다 느린 모드 여부를 `steps["slow"]`로 출력.
- `tune_pdr.py --step-method adaptive`: 전용 탐색 격자 (`slow_energy`, `adaptive_prom`, `min_quality`).

**전환 규칙을 고른 과정** (걸음 수만 비교한 시제품)

| 규칙 | 평균 | 최대 |
|---|---|---|
| **수직 흔들림 < 0.25** | **3.5%** | **6.7%** |
| 수직 흔들림 < 0.35 | 5.1% | 15.6% |
| 자기상관 품질 비교 (가속도 크기 > 수직) | 18.7% | 53.9% |
| 수직 리듬이 1.9 Hz 넘으면 2배로 판단 | 11.4% | 28.6% |

**구현 중 발견한 버그 (수정됨):** 합성 데이터 테스트에서, 서 있을 때 미세한 떨림이 "흔들림 크기로 나누기" 때문에 걸음 크기로 부풀려져 정지 구간에서 걸음이 11개 생김. → `min_energy`(0.08 m/s²) 조건 추가, 나눌 때 하한도 `min_energy`. `test_adaptive_counts_and_ignores_standing`.

**결과** (10세션 교차검증, v2 대비)

| | v2 peak | v3 adaptive |
|---|---|---|
| 걸음 수 오차 평균 | 3.1% | 4.0% |
| 매우 느린 걸음 69보 | 62보 (−10%) | 66보 (−4%) |
| 걸음 간격 이상치 합계 | 149 | **34** |
| └ 느린 폐루프 | 87 | 18 |
| 거리 오차 평균 / 최대 | 9.1 / 20.2% | 9.0 / 26.7% |

- 핵심 개선은 **걸음별 시각**. 파티클 필터는 걸음마다 위치를 옮기므로 합계보다 중요.
- 평균 오차가 약간 오른 것은 상쇄 효과가 사라진 영향.

**시도했지만 효과 없던 것:** 느린 모드 전용 보폭 계수 `length.k_slow` (`calibrate_k_mode()`). 교차검증 거리 8.3 → 8.7%. 옵션만 남김(기본 0 = 사용 안 함).

**보폭 추정의 한계 확인:** 느린 걸음 4세션의 실제 보폭은 0.23~0.33 m인데, 수직 범위·가속도 크기·수평 흔들림·기울기 회전·걸음 빈도 어느 것도 이 차이를 반영하지 못함 (모두 0.71~0.78 수준으로 비슷). **매우 느린 걸음 보폭은 몸에 단 센서만으로 ±20%가 한계** → §6 온라인 보정이 맡음.

**산출:** `pdr_tuned_v3.toml` (adaptive, slow_energy 0.3, adaptive_prom 1.2, min_quality 0.1, 지수 0.5, K 0.378)

## 6. 보폭 계수 온라인 보정

**목적:** K는 사람마다 다르고(다른 팀원·실사용자), 매우 느린 걸음은 센서만으로 보폭을 못 맞춘다. 앱 사용 중 랜드마크로 확정된 이동 거리로 K를 고쳐 나간다. (상세설계서: "수렴 후에는 서버가 추정한 이동거리로 계수를 보정한다")

**구현:** `indoornav/pdr/online_calib.py` → `StrideCalibrator`
- `add_step(t, feature, heading)`: 걸음 기록(최근 180초 보관), 현재 K로 보폭 반환.
- `correct(t0, t1, distance_m, uncertainty_m)`: 서버가 "(t0, t1] 동안 distance_m 이동"이라고 알려줄 때 호출.
  - `비율 = 실제 거리 / (K·Σfeature)`, `K ← (1−α)K + α·K·비율`, `α = max(0.2, 1/(반영 횟수+2))` (처음엔 크게).
- 반영 조건 (`CalibParams`):

| 조건 | 기본값 | 이유 |
|---|---|---|
| 구간 거리 ≥ | 5 m | 짧으면 위치 오차 비중이 큼 |
| 위치 불확실도 ≤ | 1.0 m | 서버가 확신할 때만 |
| 구간 걸음 수 ≥ | 6 | |
| 구간 방향 변화 ≤ | 20° | 서버는 두 점 사이 **직선거리**를 주므로, 꺾인 구간은 실제 걸은 거리보다 짧다 |
| 비율 범위 | 0.5~2.0 | 랜드마크 오인식 같은 이상값 차단. 사람이 바뀌면 K가 ±50%까지 다를 수 있어 여유 |
| K 범위 | 0.15~0.80 | |

**시뮬레이션:** `scripts/sim_online_calib.py` (파티클 필터가 없어서 위치 확정을 흉내 냄)
- 가정: 세션 안에서는 일정 속도로 걸었다고 보고 시각별 실제 거리를 만듦. 위치 확정 오차 σ = 0.3 m. 잡음 20회 반복 평균.
- 지표: **구간 거리 오차** = 위치 확정 사이 구간의 |PDR 거리 − 실제 거리| / 실제 거리. 파티클 필터가 확정 사이를 PDR로 버티므로 이 값이 중요.

**결과 1 — 세션마다 K=0.378(튜닝값)에서 시작** (위치 확정 5 m 간격)

| 세션 | K 고정 | 온라인 보정 | 끝 K |
|---|---|---|---|
| S1_slow_02 | 21.9% | **16.0%** | 0.351 |
| S1_slow_03 | 25.5% | **14.9%** | 0.345 |
| S1_fast_01 | 6.0% | 2.3% | 0.384 |
| L1_slow_01 | 6.4% | 5.8% | 0.420 |
| T2_normal_01 | 10.0% | 11.1% | 0.392 |
| **10세션 평균** | **9.6%** | **7.4%** | |

10 m 간격일 때 평균 9.2% → 7.6%.

**결과 2 — 다른 사람 흉내: 틀린 K로 시작해 보통·빠른 걸음 세션을 이어서 걸을 때** (정답 근처 0.378)

| 시작 K | 위치 확정 10 m 간격 | 5 m 간격 |
|---|---|---|
| 0.25 (−34%) | 0.328 → 0.347 → … → 0.373 | 0.360 → 0.369 → … → 0.396 |
| 0.55 (+46%) | 0.478 → 0.422 → … → 0.386 | 0.435 → 0.393 → … → 0.397 |

- 첫 직선 세션(16 m) 후: 5 m 간격이면 −5% / +15%, 10 m 간격이면 −13% / +26%까지 따라옴.
- 5 m 간격은 두 번째 세션(약 50 m) 후 ±4% 안, 10 m 간격은 여섯 세션(약 230 m) 후 ±3% 안.
- 10 m 간격에서 위치 확정 18회 중 11회 반영, 7회는 "구간에 회전 있음"으로 제외.

**해석과 한계**
- 매우 느린 걸음 구간 오차가 25% → 15% 수준으로 줄지만, 문서의 파티클 필터 보폭 잡음 가정(10%)보다는 여전히 크다.
- K가 이미 맞는 세션(보통 걸음)에서는 위치 확정 오차(5 m 구간에서 약 8%) 때문에 오히려 조금 흔들린다 (S1_normal_01 3.0 → 3.9%, T2 10.0 → 11.1%). 확정 간격을 넓히거나 `alpha`를 줄이면 줄어듦.
- **시뮬레이션의 가정 한계:** 실제 거리를 "일정 속도"로 만들었고, 회전 구간 직선거리 효과는 보정기 조건으로만 처리했다. 실제 파티클 필터와 연결해서 다시 검증해야 한다.

**테스트:** `test_online_calibration_converges_and_rejects` (수렴, 회전 구간 거부, 이상값 거부)

## 8. 남은 일 (우선순위 순)

1. **정지·제자리 움직임 데이터** (1분 서 있기, 서서 몸 돌리기·체중 옮기기) — adaptive의 `min_energy` 검증, 가짜 걸음 확인
2. **반복 측정** (속도별 2~3회) + **느린 걸음 발 영상** — 합계 상쇄 오차를 걸음별 정답으로 확인
3. adaptive에 **0.5초 지연 필터** 적용 (앱 이식 전 필수)
4. `slow_energy` 전환 기준이 사람마다 달라지는지 — 다른 팀원 데이터
5. 온라인 보정을 **파티클 필터와 연결**해서 재검증, 서버 응답 형식(구간·거리·불확실도) 합의
6. 세션 20개 이상 모이면 `weinberg_freq` 재비교
7. 설계서 수정 요청: 걸음 간격 "0.25~1.0초" → 실측 매우 느린 걸음 약 1.6초, 개요(1 m)와 NFR-02(1.5 m) 위치 오차 목표 통일
