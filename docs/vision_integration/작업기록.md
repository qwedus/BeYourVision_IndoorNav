**읽은 것**
- **연결은 끝까지 돈다.** indoornav PF에 비전 관측을 넣으면 출발점 앎에서 위치 오차 중앙 1.1~1.3 m로 시뮬 기준(1.1~1.2 m)과 같은 수준. 비전을 끄면 indoornav PDR + PF는 3.7 m(PDR만 3.5 m) → **비전 켬 1.3 m**
- **PDR 틀어짐 보정이 중간 설정(2 Hz·σ 10°)에서도 된다.** 시뮬 기준은 중간에서 2.5~2.8 / 5.9~9.2 m로 실패했는데, 같은 임시 PDR 걸음을 indoornav PF에 넣으면(②) 1.2 / 2.5~2.9 m. indoornav PF는 보폭 배율 k를 추정하고(끝 k 0.75~0.8 ≈ 1/1.15) 보폭 잡음이 커서(σ 15%) 틀어진 보폭을 흡수함 → 연결안 0절의 "관측 설정이 아니라 PF 움직임 모델 문제" 추정과 맞음
  - 다만 ①(시뮬 PF + indoornav PDR)도 중간에서 1.4~1.5 / 2.3~3.4 m로 보정됨. indoornav PDR 보폭 합은 66 m로 정답(걸은 길이 68 m)에 가까워 ×1.15를 해도 약 +12%인데, 임시 PDR은 0.7 m 고정 112보 = 78 m라 ×1.15면 약 +33%(90 m) → **'PDR 틀어짐' 조건이 indoornav PDR에서는 더 약함.** 같은 세기의 틀어짐에서 indoornav PF의 이득은 ② 열로 봐야 함
- **indoornav PDR(①·③)은 임시 PDR(기준·②)보다 이 녹화에서 나쁨**: PDR만 3.5 / 7.5 m vs 2.9 / 4.2 m, 비전 끔 3.5~3.7 m vs 1.9 m(어느 PF든 같음 → PF가 아니라 걸음 쪽 차이). 대합실(35~70 s)에서 PDR만 오차가 8 m까지 커짐(그림 `inav_pdr_pf/fig_error.png`). 손에 든 가로 촬영이라 조끼 고정 기준인 v4 설정 밖 — 조끼 녹화로 다시 볼 일. 비전을 켜면 차이가 거의 없어짐(1.3 m)
- **끝(3-1 문 앞) 오차**는 ③이 1.2~2.5 m로 기준(0.4~0.9 m)보다 큼. B2 구간은 짧고(16보) 비전 관측이 적음
- **방향 잡음 1.5°(5단계)**: 출발점 앎은 거의 같고, PDR 틀어짐·과신이 조금 나아짐(③ 시간 필터·중간 1.27 → 1.16 m, 오차÷불확실도 1.35 → 1.11). 결정적 차이는 아님 — 방향 잡음 키우기를 해결책으로 단정하지 않음
- **과신**: 비전 켬에서 오차÷불확실도 1.3~2.9(③). 시간 필터·중간이 가장 나음(1.3, 오차 ≤ 2×불확실도 75%, unc95 포함률 79%). '자신 있게 틀림'은 거의 모든 조건 10/10 — 시뮬 기준과 같이 정답 기준점이 의심되는 구간 영향이 큼(연결안 0절)
- **모드**: 비전 끔이면 걷는 시간의 65~73%에서 두 번째 모드(질량 > 0.1, 분리 약 4.5 m)가 있음. 비전 켬이면 0~1%
- **indoornav PF 진단**: 실행 하나에 리샘플 60~130회(걸음 128개 + 관측), 벽 제거 1.2만~2.7만 파티클·걸음(3000 × 128걸음의 약 3~7%), 전멸 복구는 거의 0회(② PDR 틀어짐·필터 없음·기본만 중앙 1회). 벽에 하나라도 막히면 강제 리샘플하는 indoornav PF 규칙(연결안 4절 P1) 때문에 리샘플이 거의 매 걸음
- **처리 시간**: 걸음 하나 predict 4 ms(N 3000)·1.8 ms(N 1000). 관측 한 프레임은 N 3000에서 약 450 ms, N 1000에서 151 ms(11개 프로세스 동시 실행이라 느리게 잼). 판 끝점·면 점을 지도에 더해 랜드마크 행이 94 → 866개가 된 것이 원인 — **비전 관측 모델 쪽 문제**(시뮬 PF도 같음). 실시간 전에 관측 모델에서 관측 종류에 맞는 행만 계산하도록 고쳐야 함(localization_design에서)

**재현성**: 각 `summary.json`의 `provenance`에 입력·지도·설정 파일 해시, 실제 PF 파라미터, seed, 라이브러리 버전(numpy 2.5.4·scipy·파이썬 3.12)을 남김. `inav_pdr_pf`는 eb598ff 커밋 전에 돌려 `branch_commit`이 9040d70(+작업 중)으로 적혀 있지만 재생 코드(`integration/*.py`)는 eb598ff와 같음. 나머지는 eb598ff(+문서만 작업 중).
