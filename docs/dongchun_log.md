# 동춘역 첫 재생 (2026-10-30 측정, 2026-10-30 분석)

경로: B01 대합실 '양쪽 출입구 갈림목' 서쪽에서 출발 → 이마트 쪽 통로 남쪽 → 점자블록 따라 서쪽 → 아래쪽 개찰구 → 에스컬레이터(→ 아래쪽 승강장) → B02 아래쪽 승강장 동쪽으로 → 왼쪽(선로 쪽)으로 꺾어 승강장 앞 정지.
세션 2개 (같은 경로, 따로 걸음): `data/dongchun/20261030_DC_B01toB02_s1` (iPhone 15 Pro), `..._s2` (iPhone 14). 둘 다 가슴 가로 장착. 걸음 수·거리 정답 없음.
설정: PDR v4, PF v3 그대로 (**튜닝 안 함**), 파티클 1000개. 재현: `uv run python scripts/run_dongchun.py data/dongchun/20261030_DC_B01toB02_s1 data/dongchun/20261030_DC_B01toB02_s2 --seeds 8`

## 지도 (`maps/dongchun/`)
- 사용자 평면도 이미지 → '걸을 수 있는 곳' 마스크 (`B01_walk.png`, `B02_walk.png`, `indoornav/pf/gridmap.py`).
- 축척·방향: 그림의 종합안내도·노선도 점을 `landmarks_Dongchun.json` 좌표에 맞춤. B01 잔차 5 cm 이하(0.0528 m/px), B02 12 cm 이하(0.0738 m/px), 회전 52.73° = 랜드마크 파일의 POI→메시 yaw 와 일치.
- 확인: 위·아래 승강장 에스컬레이터 모두 위 끝 → 아래 끝이 이미지 오른쪽으로 14.5 m (두 층 지도가 서로 맞음).
- 정답 경로 = 사용자가 그린 빨간 선 (`*_drawn_path.png`).

## 에스컬레이터 처리 (동작 랜드마크)
- 기압이 30 s 동안 가장 크게 오른 구간 = 탑승 (두 세션 모두 +0.6 hPa ≈ 5.2 m 하강).
- 탑승 중 걸음은 위치에 반영 안 함. 탑승 끝에 파티클을 위·아래 승강장 에스컬레이터 아래 끝 중 하나로 (가까울수록 높은 확률) → B02 벽이 틀린 승강장을 걸러냄.

## 해석
- **s1 (보통에 가까운 느린 걸음)**: 출발 방향만 주면 그린 경로 모양(갈림목 → 통로 → 대각선 → 개찰구)을 따라감. 보폭 배율 k 가 0.75~0.86 으로 수렴 = PDR 이 이 속도에서 보폭을 약 20% 크게 봄(집 복도 느린 걸음과 같은 경향). 탑승 직전 마지막 구간에서 동쪽으로 7~21 m 넘어감(시드마다 다름) → 에스컬레이터 위치 고정 덕에 B02 에서 회복, 최종 2.2 m.
- **s2 (매우 느린 걸음)**: 앞 170 s 동안 PDR 보폭이 거의 0 (묶음 규칙) → 같은 경로를 31 m 로 봄. PF 가 출발점 근처에 머물러 에스컬레이터에서 위쪽 승강장을 고름. 집 복도의 '극단 느림'과 같은 한계.
- **집에서 맞춘 값 그대로 역에 옮긴 첫 결과**: 보통 속도에 가까우면 통함, 매우 느린 걸음은 안 됨 (예상과 같음).
- 비전 관측(표지판)이 있으면 s1 의 B01 끝 오차, s2 의 승강장 선택 둘 다 해결될 문제 — 특히 승강장 선택은 '타는 곳' 표지 하나면 됨.

## 한계
- 정답이 '그린 선'이라 정확도 ±1~2 m. 걸음 수·거리 정답 없음.
- 마스크는 이미지 색으로 만든 것이라 글자 상자·가는 선 부근은 손으로 보정함 (`maps/dongchun/map_meta.json`).
- 평균선(파란 선)은 후보가 둘로 갈릴 때(예: 두 승강장) 사이로 그려짐 — 표시상 현상.
- 그림: `docs/figures/dongchun_s1.png`, `docs/figures/dongchun_s2.png` (중간 시드, 가장 좋은 시드 아님)

## s1 상세 분석 (2026-10-30)

### 폰 종류
- iPhone 15 Pro(s1) vs iPhone 14(s2): 정지 잡음 0.029 vs 0.029 m/s², 100 Hz 동일, 걸음당 진폭 특징 0.86 vs 0.82 → **센서 차이는 거의 없음**.
- s2 실패 원인은 폰이 아니라 걸음 속도: 걸음 간격 중앙값 2.15 s(s1 1.83 s), 2 s 넘는 간격 59%(s1 40%) → 묶음 규칙이 36% 를 보폭 0 으로 처리(s1 7%).
- 단, iPhone 14 로 보통 속도를 걸은 데이터는 없어서 '폰 무관'은 이 비교 수준의 근거.

- **헤딩은 직선 구간에서 ±4°** → 자이로 헤딩과 지도 방향(52.73° 회전) 맞춤이 둘 다 정확. E(개찰구)·H 는 실제로 비스듬히 걸었을 가능성.

- 에스컬레이터 직전 F 구간에서 여전히 5~9 m 동쪽으로 넘어감: PDR 이 +34% 길게 보고, 개찰구 뒤가 넓게 트여 벽이 잡아주지 못함. 에스컬레이터 위치 고정으로 B02 에서는 회복.
