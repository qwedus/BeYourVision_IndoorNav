# 동춘역 측정 프로토콜 (PDR 재확인 · PF 튜닝 · K 보정 검증 겸용)

집 복도(`maps/home_loop`)에서 얻은 교훈을 반영한 현장 측정 절차. 한 번 측정으로 세 가지를 같이 얻는 것이 목표.

| 목적 | 필요한 정답 |
|---|---|
| PDR 재확인 | 경로별 총거리, 총 걸음 수 |
| PF 튜닝 (랜드마크 잡음·이상치·파티클 수·복구) | 경로 중간 위치 정답 = 랜드마크를 지난 시각 + 지도 좌표 |
| K 보정 검증 | 랜드마크 사이 구간 거리 + 구간 걸음 수 |

---

## 0. 사전 준비 (현장 답사 1회)

### 지도
- 역사 평면도(안내도) 확보 → `maps/dongchun/` 에 집 복도와 같은 형식(`make_map.py` → `map.json`)으로 작성.
  - 벽·난간·개찰구 라인은 **선분**, 개찰구 통과 구간은 벽에서 뺀다(통과 가능).
  - 걷지 않을 곳(출구 계단 밖 등)은 막다른 길로 짧게만 넣는다. 다 막아버리면 PF 가 실제보다 좋아 보임.
- **좌표계**: 원점 1곳(예: 대합실 기준 기둥), +x/+y 방향, 단위 m 를 정해 문서에 적는다.
- 줄자로 핵심 치수만 실측(통로 폭, 기둥 간격, 승강장 길이 일부). 나머지는 도면 비율. 실측/추정을 `make_map.py` 에 구분해 적는다 (집 복도처럼).

### 랜드마크 목록 (`maps/dongchun/landmarks.csv`)
| 컬럼 | 예 |
|---|---|
| id | G1, P3, S2 |
| 종류 | 개찰구 / 기둥 / 표지판 / 계단입구 / 엘리베이터 / 점자블록 분기 |
| x, y | 지도 좌표 [m] |
| 지나는 기준 | "기둥 P3 옆을 지날 때", "개찰구 G1 통과 순간" 처럼 누를 시점을 한 문장으로 |

- 간격 5~10 m. **변(직선 구간) 중간 랜드마크를 반드시 포함** — 집 복도 결과에서 모서리 관측은 지도가 이미 해주는 일이라 효과가 거의 없었음.
- 비전 팀이 인식할 수 있는 대상인지 같이 확인 (나중에 Annotation 자리에 비전 결과가 들어감).

### 장비
- iPhone + 조끼 (가슴 가로 장착, **단단히 고정** — 세션 안 진폭 변화 원인 확인용)
- Sensor Logger (Annotation 사용), 카운터, 줄자, 마스킹 테이프
- 가능하면 동행자 1명 (안전·혼잡 대응, 걸음 수 세기)

### 허가·안전
- 역무실에 측정 목적 사전 안내 (카메라 동시 촬영 시 필수).
- 혼잡 시간 피하기. 개찰구 통과는 교통카드 태그 필요.

## 1. 경로 세트

현장 답사 후 아래 유형별로 1개씩 정해 `docs/routes.csv` 에 경로 ID 로 등록.

| 경로 ID | 유형 | 확인하려는 것 |
|---|---|---|
| DC_A | 승강장 길이 방향 직선 | 직선 거리·걸음 검출 |
| DC_B | 대합실 → 개찰구 → 계단 입구 (꺾임 2회 이상) | 모서리·개찰구 통과, 실제 이동 경로 |
| DC_C | 대합실 가로지르기 (넓은 공간) | **벽 도움이 없는 곳**의 PF (집 복도에 없던 조건) |
| DC_D | DC_B + 중간 10초 정지 2회 | 정지·재출발 |
| DC_E | 계단 1개 층 / 엘리베이터 (따로 1~2회) | 층 이동 (기압), 계단 걸음 |

반복: 각 경로 **보통 2회 + 느림 2회 + 역방향 1회**. 같은 조건을 최소 2개씩 — 교차검증에서 한 세션을 빼도 같은 조건이 남아야 숫자가 안정됨(집 복도 교훈).
극단 느림(0.1 m/s 미만)은 필요하면 1회만, `flag=ref` 로 참고용.

## 2. 세션 공통 루틴

1. 조끼 고정, Sensor Logger 기록 시작.
2. **출발점에서 정해진 방향을 보고 5초 정지**. 이때 Annotation 1회 (`START`) — 버튼 충격이 가속도에 찍혀 **Annotation 시계 보정** 기준이 됨 (Sensor Logger 1.68 은 Annotation 시각이 다른 시계라 필요).
3. 걷는 중 랜드마크를 지날 때마다 Annotation, 텍스트는 **`랜드마크ID/누적걸음수`** (예: `P3/32`).
   - 지난번처럼 누적 걸음 수를 적는 방식 그대로. 구간 걸음 수 정답이 되어 걸음 검출·K 보정 검증에 바로 쓰임.
   - 텍스트 입력이 어려우면 ID 만 누르고 걸음 수는 동행자가 메모.
4. 끝점에서 5초 정지 + Annotation (`END/총걸음수`) 후 기록 종료.
5. 바로 `docs/sessions.csv` 에 기록: 세션 ID, 경로 ID, 속도, 총 걸음 수, 출발점·출발 방향, 특이사항.

세션 ID: `날짜_DC_경로_속도_회차` (예: `20261105_DC_B_normal_01`).

---

## 3. 그날 확인 (현장에서 10분)

- [ ] Annotation 개수 = 지난 랜드마크 수 + 2 (START, END), 텍스트 오타 없음
- [ ] `uv run python scripts/run_pdr.py --config configs/pdr_tuned_v4.toml` 로 걸음 수가 직접 센 값과 ±5% 안
- [ ] 회전 구간이 자이로 헤딩에 보임 (꺾임 경로)
- [ ] 이상 세션은 `flag=redo` 표시 후 재측정

---

## 4. 측정 후 처리 순서 (이미 있는 도구)

1. 지도·랜드마크 작성 → `pytest tests/pf` (경로가 벽을 안 지나는지 테스트 추가)
2. PDR 재평가: `scripts/run_pdr.py` (+ 변별 분석 `scripts/analyze_legs.py`, 랜드마크 구간 기준으로 확장)
3. Annotation 시계 보정: `estimate_annotation_offset()` → 같은 날 세션은 같은 오프셋 (집 복도에서 0.3 s 안으로 일치 확인됨)
4. PF:
   - 시작값 `configs/pf_home_v3.toml` (PDR 잡음·`sigma_k`·보폭 0 처리는 그대로 가져감)
   - 역에서 새로 튜닝: 랜드마크 관측 잡음 `sigma_obs`, 이상치 `eps_obs`, 파티클 수(넓은 공간), 복구
   - 교차검증은 **경로 단위**로 하나씩 빼기
5. 비전 결과가 나오면 Annotation 자리에 비전 관측을 넣어 같은 채점으로 비교
