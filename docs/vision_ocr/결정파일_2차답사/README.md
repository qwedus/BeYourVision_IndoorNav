# 2차 답사 녹화(걸은 사람 a) Apple Vision 글자 확인 결정 파일

`vision/text_check.py` 결정 파일 형식(첫 줄 `{"engine": ...}`, 다음부터 관측 한 줄: `detection_id`, `track_id`, `t`, `label`, `decision`, `map_types`, `text_status`, `text`, `reason`)으로 만든 파일입니다. `detection_id`는 앱 기록(`decisions.jsonl`)의 값 그대로라 앱 검출을 쓰는 재생과 이어집니다.

## 녹화와 기록 이름

| 폴더 | 위치 추정 기록 이름 |
|---|---|
| OCR_30걸음 | s2_a_30steps |
| OCR_7-1_2출 | s2_a_71_ex2 |
| OCR_3출6도 | s2_a_ex3_ex6 |
| OCR_6출3도 | s2_a_ex6_ex3 |
| OCR_동막방향 | s2_a_platform |

## 파일 두 가지

| 파일 | 내용 |
|---|---|
| `text_check_applevision_app.jsonl` | 앱(0.3.3)이 현장에서 낸 판정 그대로 |
| `text_check_applevision_ocr_filter_app_v0.2.9_보강_코드.jsonl` | 앱이 읽은 글자 그대로, 보강한 판정(0.2.9)으로 다시 판정 |

- 관측마다 그 시각까지 그 판(track)에 난 판정을 붙였습니다. 확인·다른 글자가 한 번 나면 유지, 판정 전이거나 못 읽으면 `unread`, 화장실·발권기·문·역명판은 `skipped`.
- 문턱 미만·지도에 없음·크기 상한으로 앱에서 빠진 검출은 넣지 않았습니다.

## 0.2.9에서 바꾼 것

앱이 "다른 글자"로 버린 검출을 하나씩 보니 대부분 **진짜 판인데 판정 글자 목록에 없는 글자**였습니다.

| 바꾼 것 | 예 |
|---|---|
| 나가는 곳에 출구 행선지 추가 | 스퀘어원, 남동국가산업단지, 동막초등학교, 연수구청, 인천여자중학교 등 |
| 모니터 안내 문구·시각 추가 | Allow passengers to get off, THIS / NEXT, 승차·하차, 18:43 |
| 역 이름 추가 | 송도달빛축제공원, 영어 역 이름(Geomdan Lake Park, Dongmak 등) |
| 화장실 글자 | 바로잡지 않고 버림 (11-09: 천장 "← 화장실" 방향 안내판이 지도의 화장실 판과 맞춰져 위치가 틀어졌음) |
| 판정 코드 보강 3개 | 다른 종류로 바로잡을 때 첫 글자 확인("는 곳" ≠ 타는 곳), 숫자·짧은 기호는 뜻 있는 글자로 안 봄("11670"), 거리 표시("20m")는 판 글자 |

| 관측 판정 (5개 녹화 합) | 앱 그대로 | 0.2.9 |
|---|---|---|
| 확인 | 2,675 | 2,819 |
| 못 읽음 | 5,534 | 5,591 |
| **버림** | **200** | **24** |
| 종류 바로잡기 | 37 | 12 |

- 1차 녹화(route2) 재생 기록에도 같은 판정을 돌려, 광고(G20 홍보 화면 등)는 그대로 버리는 것을 확인했습니다.
- 남은 버림 24개 중 4개는 화장실 방향 안내판(일부러 버림), 나머지 일부는 흐리게 읽힌 진짜 판으로 보입니다.
- 0.2.9로 살린 판을 잘라서 확인해 보니 31개 중 29개가 진짜 판이었습니다.

## 결과

같은 녹화로 위치 추정을 재생해 본 결과, 글자 확인 끔 / 앱 그대로 / 0.2.9의 위치 오차는 거의 같았습니다(0.05~0.1 m 안팎). 결론은 상위 README를 봐 주세요.
