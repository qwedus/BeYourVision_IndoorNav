# 랜드마크 인식 OCR 보강 — 아이폰 Apple Vision 시험 결과 (2026-11-05, 김윤재)

## 한 줄 요약

아이폰에서 YOLO 결과에 **Apple Vision OCR**을 붙여 동춘역 보행 녹화로 시험했다. PC EasyOCR보다 잘 읽고, 시간 안에 돌며, 진짜 판을 버리지 않게 다듬었다. **지금 선택안은 시험 앱 0.2.7.**

## 시험 조건

- 녹화: 1차 답사(10-30) 동춘 보행 route2 (2번 출구 → 원인재 방면 3-1, 118초, 3,558프레임). PC EasyOCR 시험과 같은 영상, 위치추정 재생 시험과 같은 녹화
- 기기: 아이폰 17 계열, iOS 26, 녹화본 재생 모드(1배속 = 실시간과 같은 조건)
- 처리: YOLO(동춘 추가학습 모델, 초당 5장) → 시간 필터(최근 5장 중 3번) → OCR(판마다, 못 읽으면 0.5초 뒤 다시, 최대 3번) → 판정(확인 / 바로잡음 / 버림 / 못 읽음)
- OCR 모드: Apple Vision "정확". "빠름"은 한국어를 지원하지 않아 쓰지 않음(한글 판 220개를 광고로 잘못 버림)

## 결과 (0.2.7)

| 종류 | OCR 확인 비율 (검출마다) | 참고: PC EasyOCR |
|---|---|---|
| 남색 판(타는 곳 등) | 72% | 높이 80px 넘어야 읽힘 |
| 표 사는 곳 | 81% | |
| 나가는 곳 | 34% | 7% |
| 도착 안내 모니터 | 28% | 6% |

- OCR 때문에 버린 검출: **9개, 모두 광고**("보행 6 %" 광고 화면). 진짜 판을 버린 것 없음
- 속도: 검출 평균 14.5 ms, OCR 한 번 평균 113 ms, 밀려서 건너뛴 장 0, 발열 정상
- 반응 시간: 판을 처음 본 뒤 OCR 판정까지 보통 0.73초(느릴 때 1.3초). 대부분 시간 필터(최소 0.4초) 때문이고, OCR 자체는 약 0.1초. OCR을 기다리는 동안에도 판은 "읽는 중"으로 남겨 위치추정에 넘김
- 세는 방식이 PC 시험과 달라(PC는 판마다, 아이폰은 검출마다) 비율은 대략 비교만 가능

## 잘라낸 판을 눈으로 본 결과 (못 읽은 이유)

- **나가는 곳**: 글자가 또렷한데 비스듬한 판에서 Apple Vision이 글자 영역을 들쭉날쭉 못 찾음. 옆면(화살표만 보임)·너무 작은 판(20px 안팎)도 있음
- **모니터**: 멀리서 판 높이 55~63px이면 글자 줄이 너무 작음
- **주변지역 안내도**: YOLO가 갈색 벽을 안내도로 잡음(화면 높이 70% 넘는 박스) → 크기 상한으로 해결
- **노선도**: 진짜 노선도지만 글자가 너무 잘음
- **남색 판**: 걸을 때 흔들려 번진 장면

→ 비스듬함·작음·흔들림은 OCR 설정으로 고치기 어려움. 못 읽은 판은 **"못 읽음" 상태로 남겨 위치추정에서 낮게 믿는 것**이 맞다고 봄.

## vision-integration 결과에 대한 답 (11-04 작업기록 6절)

- "EasyOCR 판정이 버린 판 9개 중 8개가 진짜 판(흐리게 잘못 읽힘)" → **맞음, 아이폰에서도 같은 약점을 확인함.** 진짜 모니터 3건("이번일차", "This traln")을 광고로 버렸고, 0.2.6에서 판을 더 키웠을 때 잘못 읽기가 늘어 진짜 판 39개를 버림.
- 11-02 보고의 "정상을 잘못 버린 것 0"은 표본 12개 기준이었음. 전체 녹화 기준으로는 맞지 않음 — 정정함.
- 대응: 아이폰 0.2.7은 모니터 글자를 넓혀 이 녹화에서 OCR이 버린 것은 광고 9개뿐. 다만 규칙 자체는 아직 "뜻 있는 글자인데 안 맞으면 버림"이라, 흐린 녹화에서는 다시 문제될 수 있음.
- 다음: 비슷함을 자음·모음 단위로 재기. 예) "티는곳" vs "타는곳"은 지금 방식 0.67(안 맞음), 자음·모음 0.88(맞음). `sure`(안 닮은 한글만 버림)와 함께 비교해 볼 것.
- Apple Vision 결과를 결정 파일 형식으로 만들어 넘기겠음(위 표의 상태 이름 대응은 README 참고).

## 팀에 공유·제안

1. **주변지역 안내도 크기 상한(박스 높이가 화면 높이의 70% 넘으면 버림)** — PC CV 모듈 기본값에는 아직 없음. 같은 결과를 내려면 맞춰야 함
2. **OCR 상태(확인 / 못 읽음)를 관측에 붙여 넘기기** — 위치추정에서 "확인"은 더 믿고 "못 읽음"은 낮게 믿기. CV 모듈 결과의 `text` 필드에 넣는 형식 합의 필요
3. **관측은 찍은 시각 기준으로** — OCR은 0.1~0.7초 늦게 끝나지만 검출마다 프레임 시각이 남음. 녹화 재생 시연에는 문제없음. 실시간이면 늦게 온 관측을 찍은 시각의 위치에 맞춰 써야 함(그대로 지금 위치에 쓰면 5m 앞 판 기준 방향이 최대 약 9° 어긋날 수 있음, 추정)
4. **시간 필터 강도** — 지금(5장 중 3번)은 걸을 때 진짜 판도 많이 빠진다는 메모가 있음(위치추정 재생 시험 기준 47%, 직접 잰 값 아님). 느슨하게 하면 오검출이 늘어 위치 오차로 비교해서 정하자
5. **체스트 마운트 촬영은 시험 앱 기록 모드로** — 영상과 센서(걸음·자세·기압)가 함께 기록돼 흔들림 실측과 위치추정 재생에 바로 쓸 수 있음
